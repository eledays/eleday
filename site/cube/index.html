3D-куб.
Восемь точек и немного математики.

У терминала нет глубины. Есть только строки и столбцы. Но если правильно расположить несколько символов, мы увидим вращающийся объёмный куб.

Разберём код из видео как маленький графический движок. У него четыре задачи: описать форму, повернуть её, спроецировать на экран и соединить точки. Никаких 3D-библиотек — только координаты, синус и косинус.

Куб в ваших руках

Поверните куб вокруг двух осей. Расстояние до камеры меняет силу перспективы. Ниже разберём каждое действие.

8 вершин · 12 рёбер

01. Сначала — форма

Поставим центр куба в начало координат. Каждая его вершина отстоит от центра на единицу вдоль каждой оси. Поэтому координаты x, y и z принимают только два значения: −1 или +1. Длина ребра такого куба равна 2.

(x, y, z),   x, y, z ∈ {−1, +1}

Для каждой из трёх координат есть два варианта. Всего 2 × 2 × 2 = 8 вершин. Три вложенных цикла в vertices просто перебирают все сочетания.

Теперь рёбра. Соседние вершины отличаются ровно одной координатой: например, (−1, −1, −1) и (+1, −1, −1). Если отличаются две координаты, это диагональ грани; если три — диагональ куба. Условие sum(...) == 1 оставляет только соседей, а j > i не даёт посчитать одну пару дважды.

Из каждой вершины выходит три ребра. Считаем 8 × 3 и делим на два, потому что у ребра два конца. Получаем 12 рёбер.

02. Поворот — это смена координат

Начнём с плоскости. Точка на окружности радиуса r имеет координаты (r cos φ, r sin φ). При повороте на угол a она переходит в (r cos(φ + a), r sin(φ + a)). Раскрывая формулы суммы углов, получаем правило поворота.

u′ = u cos a − v sin a
v′ = u sin a + v cos a

Один поворот в плоскости YZ

Смотрим вдоль оси X. Точка начинает в (y, z) = (1, 0) и движется по окружности радиуса 1.

y′ = 1.000 · z′ = 0.000 · радиус = 1

В трёхмерном пространстве вращение вокруг X оставляет x прежним, а пару (y, z) поворачивает по этому правилу. Затем вращение вокруг Y оставляет уже полученный y прежним и меняет x и z:

y₁ = y cos a − z sin a
z₁ = y sin a + z cos a

x₂ = x cos a + z₁ sin a
z₂ = −x sin a + z₁ cos a
y₂ = y₁

Знаки во втором повороте соответствуют выбранному направлению вращения вокруг Y. В матричной записи это p′ = RY(a) RX(a) p: сначала применяется правая матрица. Матрица здесь — компактная запись линейных комбинаций координат.

RX(a) =
1   0   0
0   cos a   −sin a
0   sin a   cos a
RY(a) =
cos a   0   sin a
0   1   0
−sin a   0   cos a

Поворот сохраняет длины: для плоской пары u′² + v′² = u² + v², поскольку cos² a + sin² a = 1. Поэтому куб не растягивается. Порядок поворотов при этом важен: вокруг X, затем Y — обычно другой результат, чем вокруг Y, затем X.

В Python обе правые части присваивания y, z = (...) вычисляются до замены переменных. Иначе обновлённый y попал бы в вычисление z и испортил поворот. Функции math.sin и math.cos принимают радианы: 180° = π радиан.

03. Как глубина становится размером

Мысленно поставим камеру в (0, 0, −5), направив её вдоль +Z. Тогда глубина точки относительно камеры равна d = z + 5. На экране дальние объекты должны выглядеть меньше.

Это следует из подобия треугольников: отношение смещения на плоскости изображения к фокусному расстоянию равно отношению координаты точки к её глубине. Поэтому экранное смещение пропорционально x / d и y / d.

scale = 35 / (z + 5)
X = int(W / 2 + 2x · scale)
Y = int(H / 2 − y · scale)

Одинаковая высота, разная глубина

Отрезок слева находится на глубине d = 3. Правый имеет ту же высоту в мире, но его можно отодвигать. Показаны их размеры после проекции.

Правый отрезок: 100% высоты левого.

Число 35 задаёт масштаб изображения в строках терминала. Смещение на W / 2 и H / 2 переносит начало координат в центр экрана. Минус перед y нужен потому, что математическая ось Y направлена вверх, а номера строк растут вниз.

Множитель 2 по горизонтали компенсирует пропорции символа: ячейка терминала обычно примерно вдвое выше своей ширины. Это приближение зависит от шрифта терминала. int отбрасывает дробную часть и превращает координаты в индексы ячеек.

Делить на нулевую глубину нельзя. В исходном коде камера достаточно далеко: расстояние любой вершины до центра равно √3, поэтому z + 5 ≥ 5 − √3 > 0 при любом повороте. Для произвольных сцен понадобилось бы отсечение объектов перед камерой.

04. Из геометрии — в символы

После проекции у каждого ребра есть два конца на плоскости: A и B. Чтобы пройти между ними, используем линейную интерполяцию — взвешенную сумму концов:

P(t) = (1 − t)A + tB
x(t) = x₁ + (x₂ − x₁)t
y(t) = y₁ + (y₂ − y₁)t,   0 ≤ t ≤ 1

При t = 0 получаем A, при t = 1 — B, при t = ½ — середину. Код выбирает steps = max(|Δx|, |Δy|, 1) и перебирает t с шагом 1 / steps. По каждой оси перемещение за шаг не превышает одной ячейки. После округления записываем █ в экранный массив.

Как линия попадает в сетку

Тонкая линия — идеальный отрезок от A = (1, 1) до B = (14, 7). Закрашенные ячейки — результат округления пройденных точек. Ось Y направлена вниз, как в терминале.

t = 1 · последняя ячейка (14, 7)

Число 1 в max защищает от деления на ноль, если оба конца ребра попали в одну ячейку. Проверка границ не даёт записать символ за пределами массива. Это простой алгоритм растеризации по интерполяции; округление может повторно закрасить одну ячейку, и это нормально.

Один кадр за другим

На каждом шаге цикла создаём пустую сетку 80 × 30, поворачиваем восемь вершин, получаем восемь проекций и рисуем двенадцать рёбер. Затем соединяем символы в строки и выводим кадр.

Последовательность \033[H возвращает курсор в левый верхний угол: следующий кадр перезаписывает предыдущий. \033[?25l скрывает курсор. Очистка через clear выполняется только в начале. Анимация возникает потому, что угол a после каждого кадра увеличивается на 0.035 радиана.

Пауза 0.03 секунды даёт верхнюю оценку около 33 кадров/с: вычисления и вывод тоже занимают время. При такой паузе угол меняется примерно на 1.17 радиана в секунду, но реальная скорость зависит от терминала. Каркас рисуется целиком, включая задние рёбра: скрытие невидимых линий этот код не выполняет.

05. Полный код

Тот же алгоритм, без озвученных комментариев. Скачать cube.py. Запуск: python3 cube.py; остановка: Ctrl+C.

import math
import time
import os

vertices = [
    (x, y, z)
    for x in (-1, 1)
    for y in (-1, 1)
    for z in (-1, 1)
]

edges = [
    (i, j)
    for i in range(8)
    for j in range(i + 1, 8)
    if sum(vertices[i][k] != vertices[j][k] for k in range(3)) == 1
]

W, H = 80, 30


def rotate(x, y, z, a):
    y, z = (
        y * math.cos(a) - z * math.sin(a),
        y * math.sin(a) + z * math.cos(a)
    )
    x, z = (
        x * math.cos(a) + z * math.sin(a),
        -x * math.sin(a) + z * math.cos(a)
    )
    return x, y, z


def project(point):
    x, y, z = point
    scale = 35 / (z + 5)
    return (
        int(W / 2 + x * scale * 2),
        int(H / 2 - y * scale)
    )


def line(screen, x1, y1, x2, y2):
    steps = max(abs(x2 - x1), abs(y2 - y1), 1)
    for i in range(steps + 1):
        t = i / steps
        x = round(x1 + (x2 - x1) * t)
        y = round(y1 + (y2 - y1) * t)
        if 0 <= x < W and 0 <= y < H:
            screen[y][x] = "█"


os.system("clear")
print("\033[?25l", end="")
a = 0

while True:
    screen = [[" " for _ in range(W)] for _ in range(H)]
    points = [project(rotate(*v, a)) for v in vertices]
    for i, j in edges:
        line(screen, *points[i], *points[j])
    print("\033[H", end="")
    print("\n".join("".join(row) for row in screen), end="", flush=True)
    a += 0.035
    time.sleep(0.03)

Для исходного варианта нужен терминал с поддержкой ANSI-последовательностей и команда clear (Linux/macOS). Окно должно вмещать 80 столбцов и 30 строк; небольшой запас помогает избежать прокрутки. После остановки курсор можно вернуть командой printf '\033[?25h'. Для постоянного использования стоит завернуть цикл в try/finally и восстанавливать курсор автоматически.

Теперь за вращающимся кубом виден весь путь: координаты → поворот → перспектива → ячейки → кадр. Смените вершины и рёбра — и тот же маленький движок нарисует другую каркасную фигуру.
