# Как добавить статью

1. Выберите постоянный slug латиницей с дефисами: `how-something-works`. Создайте `site/<slug>/`.
2. Скопируйте `templates/article.html` в эту папку как `index.html`. Замените title, description, заголовок, рубрику, дату, время чтения и текст. Публичный адрес: `<slug>/`. После публикации не меняйте slug без перенаправления.
3. Добавьте ссылку и описание в список `#articles` в `site/index.html`, новые материалы — сверху. Каталог намеренно ручной, скрытой генерации нет.
4. Картинки конкретной статьи храните рядом в `images/`, код — в `article.js`, специальные стили — в `article.css`. Подключайте общий `../assets/css/main.css` первым, локальный CSS после него, скрипт — с `defer`.
5. Добавьте реальные ссылки на видео и Telegram-пост. Не публикуйте выдуманные адреса или черновые заглушки.
6. Проверьте локально, затем сделайте коммит. Push в `main` запускает публикацию.

## Общий стиль

Не переопределяйте body, темы и типографику для каждой статьи. Цвета берите из `var(--bg)`, `--surface`, `--text`, `--muted`, `--line`, `--accent`. Общие изменения вносите в `site/assets/css/main.css` и проверяйте на статье о кубе и главной. Локальные классы ограничивайте контейнером статьи или интерактива.

Используйте `.lead`, `.meta`, `.eyebrow`, `.note`, `.interactive` и `.control`; примеры есть в статье о кубе. Один h1, последовательные h2/h3, семантические section/figure/figcaption. Минимализм: без декоративных карточек в каждом абзаце, ярких градиентов и лишней анимации.

## Изображения

```html
<figure>
  <img src="./images/example.webp" alt="Содержательное описание"
       width="1200" height="800" loading="lazy" decoding="async">
  <figcaption>Что важно заметить на изображении.</figcaption>
</figure>
```

Первую заметную картинку не откладывайте через lazy. Остальные загружайте лениво; задавайте размеры для стабильной вёрстки. Сжимайте фотографии в WebP/AVIF, схемы храните в SVG. Для больших изображений используйте srcset/sizes. Соблюдайте права на материалы и указывайте источник, когда требуется.

## Интерактивы и симуляции

У каждого ползунка должен быть label и видимое значение output. Добавляйте сброс и текстовое объяснение результата, обеспечивайте управление клавиатурой. Статья должна оставаться полезной без JavaScript; для интерактива добавляйте noscript. SVG снабжайте title/desc, canvas — доступной текстовой альтернативой.

Статические схемы перерисовывают SVG при изменении параметров. Для анимаций используйте requestAnimationFrame, остановку вне экрана/в скрытой вкладке и prefers-reduced-motion; тяжёлые расчёты выносите в Worker при реальной необходимости. Не запускайте бесконечные циклы без управления. Никаких серверных секретов: всё внутри site/ публично.

## Код

Блоки — `pre > code`; длинные строки прокручиваются горизонтально. Простая подсветка статическая: span с классами `token-keyword`, `token-string`, `token-number`, `token-comment` (см. статью о кубе). Это не автоматический хайлайтер. HTML внутри примеров экранируйте (`&lt;`, `&amp;`). Если объём кода вырастет, подключение библиотеки обсуждается отдельно.

## Проверка перед публикацией

- Главная, новая статья и возврат к каталогу открываются, картинки и скрипты не дают 404.
- Проверены ширины 360px и 1280px, обе темы, длинные заголовки и код; нет горизонтальной прокрутки всей страницы.
- Ползунки и сброс работают мышью и клавиатурой; фокус виден; контент доступен без JS.
- Консоль браузера без ошибок. Пути не начинаются с `/`: это сломает project Pages под `/eleday/`.
- В публикацию не попали черновики, личные данные и тяжёлые исходники изображений.
